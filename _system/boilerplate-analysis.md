# Шаблон проекта для коллег (boilerplate)

Анализ возможности превратить текущий проект в распространяемый шаблон,
которым коллеги могут развернуть у себя. Записано 2026-08-05.

---

## Идея

Создать готовый к развёртыванию шаблон проекта на базе текущей конфигурации.
Не **skill** (skill — инструкция для агента), а **boilerplate-репозиторий**:
коллега клонирует → запускает setup → вставляет свои ключи → работает.

---

## Что переносится легко

- **`AGENTS.md`** — текст, коллега правит под свои роли
- **`.opencode/skills/`, `.opencode/agents/`** — markdown, переносится как есть
- **`tools/*.py`** — Python-скрипты, переносимы (зависимости описать в requirements)
- **`_system/`** — структура с пустыми шаблонами inventory/changelog/todo
- **`README.md`** — адаптировать под коллегу

## Что потребует настройки у каждого

- **`.env`** — у каждого свои ключи (Tavily, Figma, Telegram).
  Решение: `.env.example` с плейсхолдерами.
- **Платформы** — пути Windows (`.venv/Scripts/python.exe`) vs Linux (`.venv/bin/python`).
  Решение: setup-скрипт с автоопределением ОС.
- **Figma MCP** — требует Figma Desktop + платную подписку (~25 €/мес).
  **Главный блокер** — не у всех есть. Тут пригодится план из todo №4 (экспорт макета файлом).
- **Telegram-бот** — каждому нужен свой бот + chat ID.
- **Node.js** — для npx MCP-серверов (tavily-mcp и др.)

## Оценка трудозатрат

| Что | Сложность | Время |
|---|---|---|
| Почистить репо от рабочих данных (`_tasks/`, `design_memory.db`, `.venv/`) | низкая | 1 час |
| Сделать `.env.example` + setup-скрипт (venv, deps, init db) | средняя | 2–3 часа |
| Написать инструкцию развёртывания (step-by-step) | средняя | 2 часа |
| Адаптировать `opencode.json` под автоопределение платформы | средняя | 1 час |

**Итог:** реально за 1 день.

---

## Главный риск

**Figma MCP.** Без него проект теряет половину ценности, а настроить его у каждого
коллеги нетривиально (нужна подписка + Desktop-приложение). Если довести до конца
план №4 (работа через экспорт файла) — шаблон станет массово применимым.

---

## Что нужно для реализации

1. Очистить репозиторий от рабочих данных (оставить структуру, без содержания)
2. Создать `.env.example` с плейсхолдерами всех ключей
3. Написать `setup.sh` / `setup.bat` — создание venv, установка зависимостей,
   инициализация БД design-memory, автоопределение платформы
4. Адаптировать `opencode.json` — пути к Python под ОС
5. Написать `DEPLOY.md` — пошаговая инструкция развёртывания
6. Адаптировать `README.md` под коллег (убрать наши задачи/примеры или вынести в раздел «галерея»)
7. Проверить: клонировать на чистую машину → setup → запустить → поставить тест-задачу
