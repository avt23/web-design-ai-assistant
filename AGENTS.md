# Роли

В работе с системой участвуют две роли. Определи свою по запросу.

## Дизайнер (пользователь агента)
- Ставит задачи, получает результаты, отвечает за дизайн-решения.
- Работает только в папке `_tasks/` (задачи) и с файлами результатов.
- **Не настраивает систему**: не правит `AGENTS.md`, `.opencode/`, `tools/`, `_system/`, `.env`, MCP-конфиги, skills, субагентов.
- Если запрос касается настройки/доработки самой системы (новый skill, новый агент, MCP, промпт) — **откажись и направь дизайнера к настройщику**. Коротко: «Это задача настройщика — правки конфигурации системы я не выполняю. Передай запрос администратору.»

## Настройщик (администратор агента)
- Создаёт и правит skills, субагентов, MCP-подключения, промпты, скрипты.
- Ведёт реестр инструментов `_system/inventory.md` и журнал `_system/changelog.md` — обновляет при любом изменении.
- Фиксирует идеи и планы в `_system/todo.md`.
- Держит синхронными `_system/todo.md` (детальные планы) и `README.md` (публичная сводка): при изменении статуса плана проверяет соответствующий раздел в README.

# Варианты выполения задач пользователя
Ты можешь помогать следующим образом:
- создание лендингов-прототипов - ты получаешт поставновку задачи, данные, референсы или макет (если если). На выходе одна web-страница, ее элемент или лендинг.
- вариативное моделирование интерфейсов - здесь нужно предложить пользователю 3-5 разных варианта решеия его задачи. Исходными данными будут контент и референсы, макет
- другие задачи, которые поставит пользователь.

# Структура проекта
Ты работаешь в папке проекта и не создаешь файлов в дрегих местах.

Все задания пользователя ты обраабываешь в папке _tasks, создавая папки для запросов пользователя (задачи).
Название папки задачи делай по шаблону: <2026-07-14__current-task>

Внутри каждой папки создаешь и поддерживаешь структуру:
- папка result - здесь ты размещаешь результаты свое работы. Если нужно версионируешь при переделках, сохраняя исходную копию. Версии нумеруешь.
- папка tmp - здесь ты можешь создавать временные файлы. Это твоя раюочая директория по задаче.
- файл task.md - его может написать пользователь или ты, если задача поставлена в диалоге. При уточнении задачи отрази изменения файле task.md
- файл process.md - здесь ты фиксируешь план работы, мысли, гипотезы, посещаемые сайты и рефересы, подходы к задаче.
- файл ideas.md - здесь ты фиксирушь дизайнерские остенности задачи и ее решения

# Инструменты
Если ты видишь, что для решения задачи тебе нужно создать skill - создавай.
Если ты решил задачу и увидел, что наработки можно оформить в виде skill и применять далее - создавай.
При создании и изменении skills сообщай пользовалю об этом, чтобы он был в курсе.

Если тебе требуется использование MCP - сообщи об этом пользователю и согласуй с ним этот момент.
