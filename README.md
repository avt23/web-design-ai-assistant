# AI-ассистент веб-дизайнера

AI-ассистент на базе [opencode](https://opencode.ai) для прототипирования лендингов и веб-страниц, вариативного моделирования интерфейсов и UX-исследований. Работает с макетами Figma, референсами и описаниями задач — на выходе готовые HTML-прототипы, дизайн-токены, спецификации для верстальщика и отчёты по паттернам/антипаттернам.

Помогает продакт-командам быстро находить и сравнивать варианты решения интерфейсных задач до того, как макет уйдёт в разработку.

---

## Для кого

- **Веб-дизайнеры** — получают 3–5 вариантов раскладки/компонента с плюсами-минусами и HTML-прототипами для показа команде.
- **Верстальщики** — получают дизайн-токены (CSS/JSON), карту компонентов, спецификацию под макет Figma и готовые прототипы страниц (HTML/CSS/JS), которые можно быстро доработать и выпустить в релиз.
- **Продакт-менеджеры** — получают наглядные прототипы и сравнительные таблицы для принятия решений без ожидания полной отрисовки макета.
- **UX-исследователи** — получают сводный отчёт по современным паттернам, антипаттернам и трендам с источниками.

---

## Что умеет

| Сценарий | Что делает | На выходе |
|---|---|---|
| **Прототип по макету Figma** | Экспортирует токены, компоненты, ассеты из макета → собирает HTML-прототип по правилам проекта | `*.html` + дизайн-токены + спецификация |
| **Вариативное моделирование** | Предлагает 3–5 вариантов решения задачи с плюсами/минусами и вердиктом | Единая HTML-страница со сравнением |
| **UX-исследование** | Ищет современные паттерны и антипаттерны через веб-поиск (Tavily) | Отчёт `.md`/`.pdf` с источниками и рекомендациями |
| **Анализ макета на антипаттерны** | Экспортирует Figma + параллельно ищет антипаттерны и новые привычки пользователей | Сводный отчёт для коллег |
| **Флайер/памятка по макету** | Извлекает стиль макета → собирает HTML-файл флайера | `*.html` + ассеты + спецификация |
| **Импорт прототипа в Figma** | HTML-прототип дизайнера загружается обратно в Figma через плагин [html.to.design](https://www.figma.com/community/plugin/1159123024924461424) — получает редактируемые слои с Auto Layout | Дизайнер дорабатывает прототип агента как родной макет |

## Примеры задач

### Пример 1. Вариативное моделирование: недельное расписание нескольких объектов

**Ситуация.** Нужно наглядное отображение недельного расписания работы нескольких объектов. Количество объектов может меняться. Один объект может работать один, два или три дня в неделю и работает он всего несколько часов в день. Какие-то объекты работают утром, какие-то в середине дня, какие-то вечером. Нужно найти наглядный и запоминающийся вариант отображения. Первый вариант получился слишком вытянутым — переделан из мобильной версии.

**Что сделал агент.** Провёл UX-исследование паттернов отображения расписаний по ресурсу на десктопе, показал 6 разных вариантов (Card Grid 5-up, Stacked Rows, Resource Matrix, Master-Detail, Kanban-by-Day, Compact Pills), разобрал сильные и слабые стороны каждого. Собрал единую HTML-страницу со сравнением и итоговой рекомендацией.

**Результат.** Это позволило быстро — за один день — получить результат и согласовать его. Заказчик и дизайнер выбрали вариант E (Kanban-by-Day) — без необходимости рисовать все 6 в Figma, сэкономило время дизайнера. Решение принято за один просмотр прототипа. Выбранный вариант далее был проработан дизайнером, и в этой проработке ему также помогал AI-агент.

### Пример 2. UX-исследование: антипаттерны мобильного макета

**Ситуация.** Дизайнер параллельно сделал первую версию мобильного макета недельного графика. Нужно было учесть много факторов: несколько объектов, необходимость показа всей недели, разная наполненность дней. Неочевидно, как перейти от широкой таблицы на десктопе к узкой мобильной версии — и при этом сохранить удобство и понятность для пользователя. Плюс нужны были аргументы для защиты решения (или вариантов, если их будет несколько) перед заказчиками. Заказчик попросил оценить макет с точки зрения антипаттернов и новых привычек пользователей до вёрстки.

**Что сделал агент.** Параллельно запустил figma-exporter (дизайн-токены, компоненты, спецификация для верстальщика) и ux-researcher (антипаттерны, новые привычки 2024–2026, рекомендации). Собрал много референсов, подсказок, идей, примеров и аргументации — что делать нужно, а чего не стоит. Сведённый отчёт отправлен коллегам.

**Результат.** Дизайнер высоко оценил работу: современные тренды и хорошо работающая классика в одном пакете — отличный материал для проектирования. Работа идёт уже не на интуиции, а на хорошей и аргументированной базе. В итоге всё делается быстрее и с многократно меньшими тратами сил.

### Пример 3. Флайер по макету Figma: памятка об ЭТрН

**Ситуация.** Компания готовится к введению электронной транспортной накладной с 1 сентября. Нужна памятка-флайер для клиентов: кратко о нововведении и приглашение к совместному тестированию. Есть макет Figma, текст менять нельзя — только точечные акценты. Нужно сделать очень быстро, при этом информация должна легко восприниматься и запоминаться. Нет времени на итерационную работу.

**Что сделал агент.** Экспортировал токены, структуру и ассеты из Figma, исследовал 10 референсов подачи подобных памяток (onboarding клиентов). Собрал сводный HTML-файл с 6 разными вариантами подачи для сравнения.

**Результат.** Дизайнер выбрал из 6 вариантов три (1, 5, 6) и агент выгрузил по ним подробную спецификацию: структура, размеры, цвета, отступы. В итоге всё очень быстро согласовали и подготовили файлы к печати.

## Как устроен проект

```
.
├── AGENTS.md              # Промпт агента: роли, правила, структура задач
├── _tasks/                # Папки задач дизайнера (по дате + теме)
│   └── YYYY-MM-DD__task-slug/
│       ├── task.md        # Постановка задачи
│       ├── process.md     # Ход работы, гипотезы, источники
│       ├── ideas.md        # Дизайнерские нюансы решения
│       ├── result/         # Результаты (HTML, токены, отчёты)
│       └── tmp/            # Временные файлы
├── _system/               # Инфраструктура (ведёт настройщик)
│   ├── inventory.md       # Реестр инструментов: skills, субагенты, MCP, скрипты
│   ├── changelog.md       # Журнал изменений системы
│   └── todo.md            # Идеи и планы развития
├── .opencode/             # Конфигурация opencode: skills, субагенты, MCP
│   ├── opencode.json      # MCP-подключения (Tavily, Figma, Telegram, design-memory)
│   ├── skills/            # Skills (маршрутизация задач и др.)
│   └── agents/            # Субагенты (figma-exporter, ux-researcher, telegram-bridge)
├── tools/                 # Скрипты MCP-серверов (telegram, design-memory)
├── docs/screenshots/      # Скриншоты для README
└── .env                   # Ключи API (TAVILY, FIGMA, TELEGRAM)
```

### Роли

- **Дизайнер** — ставит задачи в `_tasks/`, получает результаты, информируется через Telegram. Не настраивает систему.
- **Настройщик** — создаёт/правит skills, субагентов, MCP, промпты, ведёт реестр в `_system/`.

### Инструменты

- **MCP Tavily** — веб-поиск, extract, crawl, research для UX-исследований
- **MCP Figma** — экспорт токенов, компонентов, ассетов из макетов
- **MCP Telegram** — уведомления дизайнера о завершении задач
- **MCP design-memory** — память по задачам: реплики, решения, поиск
- **Skills** — `design-task-router` маршрутизирует задачи по субагентам
- **Субагенты** — `figma-exporter`, `ux-researcher`, `telegram-bridge`

Подробно — в [`_system/inventory.md`](_system/inventory.md).

## Интеграция с Figma

Проект использует **MCP-сервер Figma** для извлечения дизайн-токенов, структуры компонентов, ассетов и спецификаций из макетов. Существует два варианта подключения — мы прошли через оба.

### Вариант 1. Прямой доступ по API-ключу (отключён)

`figma-developer-mcp` работает напрямую с сервером Figma по API-ключу (`FIGMA_TOKEN`). Не требует оплаты подписки Figma.

**Что случилось.** При попытке подключить взаимодействие AI-агента и дизайнера через Telegram было много попыток с потерями контекста. Похоже, из-за этого нас могли заблокировать на стороне Figma — начали регулярно получать `429 Too Many Requests`.

**Итог.** Вариант отключён в `.opencode/opencode.json` (`figma-developer-mcp.enabled = false`).

### Вариант 2. Локальный MCP-мост Figma Desktop (включён, текущий)

Обходное решение. На ноутбук устанавливается приложение Figma Desktop, и MCP-сервер Figma поднимается на нём через локальный мост `http://127.0.0.1:3845/mcp` (`figma` в `.opencode/opencode.json`).

**Особенности:**
- Работает, пока активна платная подписка Figma (~20 € + 5 € налог в месяц).
- MCP-сервер Figma официально не поддерживает opencode напрямую — мы используем его через dev-mode и локальный мост.
- **Нельзя перенести на VPS**: MCP-сервер привязан к Figma Desktop на конкретной машине. Это блокирует идею автономной работы агента на удалённом сервере.

### Открытые вопросы

- Нужен способ работы с макетами Figma без постоянного подключения к сервису — например, через **экспорт макета** в файл (`.fig`, JSON, изображение) и обработку этого файла агентом. Это позволит:
  - избавиться от платной подписки Figma,
  - уйти от риска блокировок (429),
  - перенести проект на VPS.
- См. `_system/todo.md` — пункт «Проверить варианты взаимодействия с Figma через экспорт макета».

## Быстрый старт

1. Установите [opencode](https://opencode.ai) и [Node.js](https://nodejs.org/).
2. Клонируйте репозиторий, создайте `.env` с ключами:
   ```
   TAVILY_API_KEY=...
   FIGMA_TOKEN=...
   TELEGRAM_BOT_TOKEN=...
   TELEGRAM_CHAT_ID=...
   ```
3. Создайте Python venv и установите зависимости MCP-серверов:
   ```bash
   python -m venv .venv
   source .venv/Scripts/activate   # Windows (Git Bash)
   # или: source .venv/bin/activate  # Linux/macOS
   pip install python-telegram-bot
   ```
4. Запустите opencode в корне проекта — конфигурация подхватится из `.opencode/opencode.json`.
5. Поставьте первую задачу: попросите агента сделать прототип лендинга или оценить макет Figma.

## Планы развития

Подробные планы с чек-листами — в [`_system/todo.md`](_system/todo.md). Ниже — краткая сводка.

### Перенос на VPS

Перенести проект на VPS для автономной работы дизайнера в любое время. На VPS настройщик настраивает систему один раз, дизайнер только пользуется. **Блокируется интеграцией с Figma** — текущий локальный MCP-мост нельзя перенести на сервер.

### Интеграция с Figma через экспорт макета

Текущая интеграция (локальный MCP-мост через Figma Desktop) требует платной подписки и привязана к машине. Нужен способ работы с макетами без постоянного подключения — например, через экспорт макета в файл и обработку его агентом. Это разблокирует перенос на VPS и избавит от риска блокировок (429).

### Двусторонняя работа с агентом через Telegram

Сейчас Telegram-мост работает в одну сторону — агент отправляет готовые файлы и отчёты. Цель — полноценное двустороннее взаимодействие: дизайнер ставит задачи, уточняет запросы, отвечает на вопросы агента — всё через Telegram, без терминала. Особенно важно для работы с телефона и после переноса на VPS.

### Инструментарий для работы с графикой

Агент не «видит» картинки — не может анализировать макеты, референсы, эскизы, скриншоты визуально. Нужны инструменты передачи изображений в модель (vision, OCR, MCP для анализа графики), чтобы агент мог оценивать компоновку, сравнивать референсы и работать с эскизами дизайнера.

### Шаблон проекта для коллег (boilerplate)

Идея — превратить проект в готовый к развёртыванию шаблон: коллега клонирует → запускает setup → вставляет свои ключи → работает. Главный блокер — Figma MCP (нужна подписка + Desktop-приложение), поэтому шаблон становится массово применимым только после решения задачи экспорта макета файлом. Подробный анализ — в [`_system/boilerplate-analysis.md`](_system/boilerplate-analysis.md).
